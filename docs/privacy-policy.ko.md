# Kibitzer 개인정보 처리방침

- **운영자**: 이은우 (Kibitzer 개발자)
- **문의**: [GitHub Issues](https://github.com/enu3379/kibitzer/issues)
- **발효일**: 2026-07-30

Kibitzer는 사용자가 선언한 목표와 브라우징 흐름을 비교해, 주의가 흐트러질 때만 한마디 건네는 Chrome 확장 프로그램입니다. **자체 서버가 없으며**, 모든 판정·상태·기록은 사용자의 브라우저 안에서만 처리·보관됩니다.

## 1. 수집하지 않는 것

- Kibitzer 운영자는 어떤 데이터도 수집하지 않습니다. 운영자 서버가 존재하지 않고, 원격 분석(analytics)·광고·추적 코드가 없습니다.
- 방문 페이지의 원시 URL(경로·쿼리·프래그먼트), 로컬 PDF의 파일 경로·본문, 계정 정보, 폼 입력은 어디에도 저장·전송되지 않습니다.

## 2. 브라우저 안에만 저장되는 것

아래 데이터는 확장 프로그램의 로컬 저장소(IndexedDB, chrome.storage.local)에만 보관됩니다.

- 선언한 목표와 세션 상태(몰입 게이지)
- 관측 기록: 페이지 **제목과 호스트명**, 그리고 경로·쿼리의 해시값 (원시 경로/쿼리는 저장하지 않음)
- 사용자가 설정에서 로컬 PDF 관측을 켠 경우: Chrome이 표시하는 **문서 제목(없으면 파일명)**과 `local-pdf` 표지 (원시 파일 경로는 저장·전송하지 않고 PDF 본문은 읽지 않음)
- 판정 결과(OK/DRIFT), 훈수 메시지, 세션 요약, 학습된 목표 예시(임베딩 벡터)
- 진단 로그 (민감 사이트는 호스트명 없이 카테고리만 기록)

**설정 → 모든 활동 데이터 삭제**로 활동 기록을 언제든 지울 수 있습니다(목표·API 키·페르소나 설정은 명시적으로 별도 삭제). 확장 프로그램을 제거하면 전부 삭제됩니다.

## 3. 외부로 전송되는 것 (선택 기능)

AI 판정(Tier 1/2)은 **사용자가 직접 API 키를 등록한 경우에만** 동작합니다. 키를 등록하지 않으면 모든 판정이 기기 내 로컬 모델(Tier 0)로만 이루어지며, 아무것도 외부로 전송되지 않습니다.

키를 등록하면, 판정 시점에 다음 항목이 **사용자가 선택한 LLM 제공자에게만** 전송됩니다.

- 선언한 목표 텍스트
- 현재 페이지의 제목과 호스트명 (원시 URL 제외)
- 최근 페이지 제목들과 판정 결과
- (Tier-2 판정 시) 현재 페이지 본문 발췌 최대 3,000자 — 판정 직전에만 읽으며, 저장하지 않음
- 판정 점수·시간 예산 등 컴팩트한 컨텍스트

로컬 PDF 관측은 기본으로 꺼져 있습니다. 사용자가 설정에서 직접 켜면 PDF 제목도 위의 현재·최근 페이지 제목과 같은 방식으로 선택한 LLM 제공자에게 전송될 수 있습니다. 원시 파일 경로와 PDF 본문은 전송되지 않습니다.

판정 시점 외에 두 시점에도 같은 범주의 데이터가 전송됩니다: 목표를 선언한 직후 목표 텍스트를 판정 예시로 보강할 때, 그리고 세션을 마치며 요약을 쓸 때(목표, 가장 오래 머문 페이지 최대 5곳의 제목·호스트명·체류 시간·판정 결과, 세션 통계, 훈수 횟수).

전송 대상은 사용자가 설정에서 선택한 제공자로 한정되며, 지원 목록은 다음과 같습니다: Ollama Cloud, Google Gemini, OpenRouter, DeepSeek, Anthropic Claude, OpenAI, Moonshot Kimi. 각 제공자의 데이터 처리에는 해당 회사의 개인정보 정책이 적용됩니다. 전송은 전부 HTTPS이며, 제공자 주소는 코드에 고정되어 있어 임의 서버로 보낼 수 없습니다.

## 4. 민감한 사이트는 관측하지 않습니다

은행·카드·증권·결제·의료·정부 민원·웹메일·로그인 페이지 등 내장 [민감 도메인 목록](https://github.com/enu3379/kibitzer/blob/main/configs/sensitive_domains.json)에 해당하는 사이트는 **판정·기록·전송 대상에서 원천 제외**됩니다. 몰입 게이지는 중립으로 멈추고, 해당 사이트의 제목·본문은 확장프로그램이 읽지 않으며, 진단 로그에도 사이트 이름이 남지 않습니다. 시크릿 창에서는 확장 자체가 동작하지 않습니다.

## 5. API 키 보관

- API 키는 사용자의 브라우저 `chrome.storage.local`에 저장됩니다(운영자에게 전송되지 않음). 저장소 특성상 평문 보관이며, 기기를 공유하는 경우 이 점을 유의하세요.
- 화면에는 항상 마스킹된 형태로만 표시되고, 진단 로그·내보내기 파일·오류 메시지에 포함되지 않습니다.
- 키는 해당 제공자의 API 호출 인증에만 사용됩니다.

## 6. 데이터 내보내기

설정의 이벤트 로그/디버그 로그 내보내기는 **사용자가 직접 실행할 때만** `~/Downloads`에 파일을 만듭니다. 파일에는 제목·호스트·판정·훈수 메시지가 포함될 수 있으나 API 키·원시 URL·페이지 본문은 포함되지 않습니다. 파일 관리는 사용자 책임입니다.

## 7. 방침 변경

방침이 바뀌면 이 문서와 발효일을 갱신하고, 중요한 변경은 릴리스 노트에 고지합니다. 이 문서의 이력은 [GitHub 저장소](https://github.com/enu3379/kibitzer)에서 확인할 수 있습니다.
